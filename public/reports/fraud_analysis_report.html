Fraud Detection: three datasets, one cost function

A fraud model can be 99.8% accurate and catch zero fraud. This report measures what matters instead, sets the decision threshold from the cost of a missed fraud, and reports every result with its uncertainty.

The accuracy paradox, measured. On Bank Account Application Fraud, a model that predicts "never fraud" for every transaction scores 98.90% accuracy and catches zero of the 441 frauds. Its average precision is 0.0110 - exactly the base rate, which is what "no better than chance" looks like.

Why average precision and not accuracy or ROC-AUC? Below a 1% base rate, accuracy is dominated by the majority class and ROC-AUC by the true-negative mass - both stay flattering for models that are not useful. Average precision summarises the precision-recall curve, which is the curve a fraud team operates on.

5. Cost-based threshold selection

The objective is Z = $100 x FN + $1 x FP. The 0.5 default is optimal only when a missed fraud costs the same as a false alarm, which it never does.

7. What drives the predictions

Coefficients come from a separate unpenalised logistic fit on unresampled training data, because scikit-learn's penalised fit provides no valid standard errors. Features are standardised, so exp(β) is the odds multiplier per one standard deviation.

Impurity and gain importance are computed on training data and favour high-cardinality continuous features. Permutation importance is measured on the held-out split against average precision - the defensible one. These are associations, not causes.

8. Limitations and next steps

  • Small positive counts. The Credit Card test split holds 98 fraud cases; every interval is wide and the top models are largely indistinguishable.
  • Sampled data. Two datasets are capped at 200,000 rows - an explicit compute budget.
  • Probabilities are not calibrated to the population base rate when class weighting is used. Rankings and odds ratios are unaffected.
  • The cost ratio is an assumption, not a measurement.
  • Evaluation is static - no drift, no adversarial adaptation, no analyst feedback loop.

Next: temporal validation on the Bank Account month column; probability calibration so the cost-optimal threshold matches its theoretical value; graph features for application fraud; cost-sensitive learning in place of post-hoc thresholding.

The dataset that did not work has its own post-mortem.
